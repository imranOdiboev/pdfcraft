## 1. Границы и отсутствующий референс

В доступном сообщении нет изображения нового визуального концепта. Старые изображения
ODIBO — логотип и иконка, а не новый UI-референс. Поэтому **визуальное сравнение с новым

нужно повторно приложить концепт либо явно принять предложенные ниже макеты по текстовому brief.

Это не замена egui: HTML/CSS ниже — только переносимые проектные материалы.
Они не входят в приложение, Cargo, Windows ZIP или Web-продукт. PDF-кнопки в макетах
не подключены и не изображаются как работающая новая версия. Реализация, Windows-сборка
и отдельный продуктовый PR — после согласования структуры и макетов.

Не менялись Rust/egui-код, PDF-ядро, CLI/MCP, пользовательские документы, настройки,
локализации, Cargo.lock, существующие сборочные workflow или брендовые ресурсы.
Добавлен только отдельный workflow для рендеринга проектных материалов на стандартном
Ubuntu runner, без установки чего-либо на компьютер владельца. Релиз и merge не выполняются.

## 4. Предложенная структура

### Dashboard

Header: имеющийся знак ODIBO, имя, Ctrl+K, тема и штатные window controls.
Слева: Главная, Последние, Все инструменты, Папки; внизу Настройки/Помощь.
По центру: Open PDF как основной акцент, остальные 7 задач, затем Recent и доступ к папкам.
Recent остаётся локальным, без генерации новых копий PDF/превью на диске и без облака.
Если список пуст — краткое объяснение, Open и существующий drag-and-drop; отсутствующий
файл не удаляется с диска и не считается успешно открытым.

### Редактор

1. Header: Главная, Open, вкладки документов с dirty marker, Undo/Redo, Save, Ctrl+K, тема.
2. Строка задач: Просмотр, Редактирование, Аннотации, Страницы, Формы, Ещё.
3. Контекстная toolbar: только команды текущей задачи; всегда понятное активное состояние.
4. Слева: Страницы / Закладки. Центр: прежний canvas и белая PDF-страница в обеих UI-темах
   (настройки reading colours пользователя сохраняются). Справа: свойства выбранного объекта,
   комментарии, поля или другой выбранный инспектор.
5. Внизу: номер страницы, PDF zoom, fit controls, ясный статус несохранённых изменений.

Строка задач — **представление существующих возможностей**, не замена сериализуемого Mode
на новые несовместимые значения. `all/read/edit/convert/sign`, CLI flags и control options остаются.
Все инструменты, подписи/сертификаты, OCR, redaction, защита, preflight, вложения,
layers, accessibility, search/compare и прочие существующие возможности сохраняются в
каталоге/меню/Ctrl+K. Никаких декоративных cloud/AI/share/аккаунт-кнопок.

### Объединение и организация

Combine остаётся существующей отдельной вкладкой: список/сетка, добавить файлы, изменить
порядок, убрать из списка, объединить, затем явно сохранить результат. Убрать из списка
не означает удалить исходный файл. Показывать реальное число файлов/страниц после чтения.
Organize использует существующий grid, selection и page operations; не новую модель страниц.
Предусмотреть кнопки перемещения как альтернативу drag-and-drop.

## 5. Экран → существующие действия

| Вход | Реальный путь | Условия/ограничения |
|---|---|---|
| Dashboard · Открыть PDF | `file.open`, `open_dialog()` | File picker/drop; cancel ничего не меняет |
| Редактировать | `run_command("edit.edit_text")` | Сначала открыть PDF при необходимости; `Needs::Modification`; без обещания Word-подобной перевёрстки любого PDF |
| Объединить | `page.combine`, `combine_ui` | `Needs::Nothing`; отдельная вкладка, прежние открытые документы и их undo не теряются |
| Разделить | `run_command("page.split")` | `Needs::Assembly`; прежний диалог и правила сохранения/отказов |
| Аннотации | `run_command("comment.note")`, каталог `comment` | После открытия — инструмент заметки; запись только после действия на странице. `comment.highlight`, underline, strikeout, ink, shapes и список доступны из панели; права Annotate сохраняются |
| Формы · заполнить | Open, затем `form.fields` / существующее заполнение canvas | Показать поля; не создавать новые поля автоматически. Пустая форма — понятное состояние |
| Формы · подготовить | `run_command("form.prepare")`, `form.add.*`, `form.detect` | Отдельный явный выбор, `Needs::Modification`, сохранить Edit/Preview и tab order |
| Организация страниц | `run_command("page.organize")`, затем `page.rotate/insert/delete/extract/replace/duplicate/reverse/number` | Просмотр grid не равен разрешению менять PDF; Needs каждой операции сохраняется |
| Экспорт | Каталог `export`, затем выбранный `export.docx/image/all_images/pptx/html/rtf/text` | Выбор формата и существующий run_command. XLSX/PS не показывать готовыми, fidelity conversion остаётся частичным |
| Recent / папки | `open_recent`, `folders_ui`, `file.clear_recent` | Не менять текущую историю/пути. Очистка Recent удаляет запись, не документ |
| Header | `file.save`, `file.save_as`, `edit.undo/redo`, `file.open`, `view.palette`, `app.preferences`, `view.theme.*` | В Combine undo/redo работают с его списком — сохранить текущую специальную обработку |
| Навигация | Существующие Pages/Bookmarks, `DocView`, page navigation и layout/zoom | Сохранить page labels, multi-selection, drag-reorder, историю вида; перенос body слева — будущая UI-работа |
| Свойства текста | `panels::format_section`, `content_ui::format_panel`, `apply_line_format` | Только реально поддерживаемые свойства/исходные шрифты; не создавать параллельный undo/state |
| Контекст других объектов | Существующие image/comment/form controls | При отсутствии подходящего выделения — инструкции/обычные инструменты, не фиктивные значения |

Одна карточка ≠ новая engine-функция. Если требуется выбор поддействия (Forms/Export),
это честный UI-chooser. Если действие запрещено PDF-permissions или read-only режимом,
показать причину; не обходить `command_enabled`/`Needs`. Registration ≠ полная fidelity.

## 6. Реализуемость в egui и адаптивность

Frames с CornerRadius 6–12 pt, обычные egui Buttons/SelectableLabel, Panel, ScrollArea,
Grid/горизонтальные layouts, уже имеющийся docking, popup/menu, ComboBox и text layout
достаточны. Без CSS-эффектов стекла, сложной анимации, нового DOM UI или нового фреймворка
в продукте. Форматирование PDF остаётся в существующих view-модулях.

Предварительные размеры: spacing 4/8/12/16/24/32; controls 36–40 pt; icon 18–20 pt;
Inter 14/16, заголовки 20/28; левая навигация 156–210 pt, правый контекст 260–300 pt.
Это дизайн-токены, **не новые жёсткие ограничения docking**: точные min sizes уточнить
после egui-прототипа. Радиусы и тени умеренные; PDF page shadow уже поддержан.

| Доступная ширина в логических egui pt | Поведение |
|---|---|
| ≥1280 | Навигация + canvas + инспектор; Dashboard 4 колонки |
| 1000–1279 | Более узкая навигация; инспектор по запросу; Dashboard 3 колонки |
| 800–999 | Dashboard 2 колонки; inspector временно скрыт, доступен через подписанную кнопку; toolbar overflow |
| <800 или большая системная шкала текста | Одна вспомогательная панель по запросу, документ остаётся доступен; вертикальный scroll, без обрезания Save/Cancel и без горизонтального скролла всего окна |

Пороги предварительные и считаются по **available logical width**, не разрешению монитора.
1920 px при 200% — примерно 960 logical pt; 1366 px при 150% — около 911 pt.
CSS-макеты проверяют композицию, а не удостоверяют реальный Windows DPI/egui raster.
В реализации потребуются 100/125/150/175/200%, перенос окна между мониторами,
Windows text scale, длинные RU/EN строки и минимум 800×600 logical viewport.

## 7. Сохранение данных, layout и автоматизации

- Никакого сброса текущих настроек и нового переноса per-user/portable папок. История,
  автосохранение, recovery, dirty state, сохраняемые позиции/масштабы документов остаются.
- UI v2 — версия presentation-layout с безопасным чтением старого docking. Сохранить
  исходный layout и возможность Classic/возврата. Для существующего профиля применять
  новую компоновку только по явному выбору; для нового — новый default после согласования.
- Существующие `canvas/tools/inspector` IDs и `ui.dock` команды сохраняются. Новая Navigation
  — отдельный optional panel/вид, а не переименование сериализованных старых panel IDs.
  Точная схема добавления и migration tests — часть 3.4, до изменения формата данных.
- Вынести общий рендеринг Pages/Bookmarks из `right_panel` с отдельным view state,
  не дублируя DocView/Session. Сохранить совместимость явного `--right pages`/control options:
  такой запрос должен оставаться выполнимым, без двух одновременно активных копий одной навигации.
- На узком окне скрывать панели в render projection, не сохранять это как новую волю пользователя.
  Не менять размеры плавающих групп, скрытые locations, protected Canvas и Read/fullscreen поведение.
- `switch_mode` должен сначала завершить/применить текущий editor draft по существующим правилам;
  не присваивать `mode` напрямую из новых кнопок. Сохранить deferred shortcuts и dialog precedence.
- Все новые UI routes используют прежние engine commands/automation API. Control остаётся
  opt-in, loopback и token-authenticated; MCP не запускается автоматически.

## 8. Доступность, клавиатура, локализация и состояния

Нативные egui widgets с `WidgetInfo`, полными accessible names, видимым focus ring и
правильным enabled/selected-state. Painter-only карточки не должны терять focus/keyboard.
Tab/Shift+Tab обходят действия; Enter/Space активируют; Esc закрывает верхний popup/modal,
а не документ. Ctrl+O/S/Shift+S/Z/Shift+Z/F/K и текущая таблица shortcuts сохраняются;
ввод текста в поле имеет приоритет над глобальным hotkey. Drag имеет кнопочную альтернативу.

Контраст — целевые ≥4.5:1 для обычного текста, ≥3:1 для UI/focus; это цель, не декларация
WCAG-сертификации. Не передавать значение только цветом. Reduced motion сохраняется.
Нужна отдельная проверка AccessKit/Narrator в реальном приложении.

RU и EN — обязательные проходы; для остальных 20 каталогов не отключать coverage.
Сохранять английские lookup keys, command IDs, `tr_id`, plurals и placeholders; новые
строки добавлять во все каталоги по существующему процессу. Имена/текст PDF не переводить.

Обязательные состояния: пустой Recent; отсутствующий файл; loading/cancel/error/password;
read-only и недостаток permissions; scan без текстового слоя (OCR доступен отдельно, без
автоматического обещания распознавания); dirty tab; failed save; отсутствующие form fields;
нет подходящего выделения; недоступный export/provider. Панели не должны скрывать ошибки.

| 3.5 · контекстные панели | Text/image/comments/forms, компактный overflow, сохранение advanced tools | Высокая · 4–6 | Несогласованный selection/undo и потеря функций; сценарии каждого семейства |

| 3.7 · поставка | Проверенный Windows ZIP, notices, SHA, отдельный PR и отчёт | Низкая/средняя · 1–2 | Подпись/MSI/официальный релиз не входят; не маскировать skips |

Сумма: **21–32 рабочих дня**, плюс резерв 20–30% на docking и accessibility.
Первый промежуточный результат — tokens + Dashboard, около 5–8 дней после утверждения.
Не объединять глобальную замену layout и правки PDF-ядра в один шаг.

## 10. Проверки будущей реализации и участие владельца

Автоматически: fmt/Clippy, workspace/targeted tests, layers/assets/parity, RustSec,
WASM compatibility, CLI/MCP/root safety, UI control/keyboard/AccessKit tree и snapshot
states; синтетический PDF open/combine/split/save/reopen и source preservation.
Не писать тесты, проверяющие лишь совпадение цвета с константой: важны достижимость,
состояние, отсутствие перекрытий, сохранность draft/layout/document и ошибки.

Владелец: прислать недоступный концепт или принять предложенные макеты; утвердить структуру
и поведение Classic/new layout; проверить «найти действие → выполнить → сохранить» на
Windows, мышью/клавиатурой, на своём DPI/мониторе; оценить скриншоты и читаемость.
Исполнитель: UI-код после разрешения, dispatcher, тесты, локализации, Actions, notices,
артефакты и PR. Установка программ на компьютер владельца не требуется.

До разрешения реализации не менять файлы `apps/`, `crates/`, `assets/`, `Cargo*`,
`ATTRIBUTION.*` и существующие продуктовые workflows. У текущего шага только план,
макеты и их отдельный renderer. Продуктовый PR создаётся на этапе реализации, не здесь.

## 11. Макеты, происхождение и как смотреть

[Открыть локальную галерею](preview.html). Макеты можно открыть обычным браузером;
требуется сохранённая структура репозитория для CSS, имеющихся Inter/Lucide/ODIBO файлов.
PNG-экспорты рендерятся только отдельным Actions workflow и не коммитятся в репозиторий.

1. Dashboard RU light / dark, 1440×980.
2. Редактор RU light / dark, 1440×980.
3. Компактный редактор RU, 960×800; контекст справа временно скрыт, доступен кнопкой.
4. Dashboard EN, 1440×980, для проверки длины подписей.
5. Combine RU, 1440×980, пример отдельной рабочей задачи.

Все записи Recent, имена, размеры/числа страниц и содержимое документа — синтетические
данные макета, не прочитанные PDF и не личные файлы. HTML/CSS — авторский проектный код
IMR4N / Codex, `MIT OR Apache-2.0`; это не распространяет кодовую лицензию на бренд.
Повторно используются неизменённые `assets/odibo/icon-64.png` (LicenseRef-ODIBO-Brand),
Lucide SVG из `assets/icons/` (ISC) и Inter из `assets/fonts/` (OFL-1.1).
Новых внешних изображений/шрифтов, генеративных вариантов логотипа и Adobe-материалов нет.
SHA и первичные notices исходных ресурсов уже в ATTRIBUTION.toml; он не меняется.
Каждый экспортируемый PNG получает SHA/provenance/source commit в артефакте,
с копиями MIT/Apache/NOTICE, Lucide ISC, Inter OFL и условий бренда.

Рендер браузером проверяет вид **макетов**, а не компиляцию или работоспособность
изменённого egui-приложения. Новые Rust-тесты/Windows EXE на этапе 3.1 не создаются.
