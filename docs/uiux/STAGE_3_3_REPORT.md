## Реализованный кандидат

Home использует токены egui этапа 3.2: подписи 14 pt, второстепенный текст 12 pt,
фирменный синий акцент, существующие ODIBO-логотип, Lucide и встроенные шрифты.
Число колонок зависит от доступной логической ширины: от одной до четырёх.
Кнопка открытия выделена контуром. Карточки и строки недавних файлов показывают
клавиатурный фокус; удаление записи Recent доступно также при фокусе строки.
При недостаточной высоте используется прежняя вертикальная прокрутка.

| Карточка | Реальная команда / результат |
| --- | --- |
| Открыть | `file.open`, существующий асинхронный выбор файла |
| Объединить | `page.combine`, прежняя отдельная вкладка Combine |
| Разделить | `page.split`, выбор документа, затем существующий Split |
| Редактировать | `edit.edit_text`, выбор документа, инструмент текста/изображений |
| Аннотации | `comment.note`, выбор документа, инструмент заметки; другие аннотации в прежнем каталоге |
| Подпись | `sign.fill.signature`, выбор документа, существующая Fill & Sign; это не обещание сертификатной подписи |
| Организация | `page.organize`, выбор документа, существующая сетка страниц |

Все карточки вызывают `run_command`; сохраняются ограничения прав PDF и обработка
отмены/ошибок выбора. Никаких новых действий PDF или параллельного состояния операций.
На Web сохраняется прежнее поведение: после браузерного открытия инструмент выбирают
повторно. Основная проверяемая платформа этого этапа — Windows x64.

Recent расположен сразу после карточек: прежние `open_recent`, фокус уже открытой
вкладки, открытие файла с диска, очистка/удаление записи без удаления самого файла,
пустое состояние. Сохранены закреплённые папки, ссылки проекта и информация о приватности.
Длинные имена/пути используют прежнее сокращение с полным путём в подсказке.

Панели редактора, PDF-ядро, CLI/MCP, зависимости, схема настроек и пользовательские
документы не менялись. Лицензии MIT/Apache-2.0 и исходные уведомления сохранены;
брендовые материалы остаются под `LicenseRef-ODIBO-Brand`. Новых ассетов нет.
Переводы действий используются из существующих каталогов, для двух новых заголовков
добавлен русский перевод; остальные локализации сохраняют штатный английский fallback.

Причина: push и создание PR не создали ни одного задания; явный `workflow_dispatch`
вернул HTTP 422: **“Actions has been disabled for this repository.”** Владелец должен
включить выполнение workflow. После сообщения владельца о включении настройки проверены
через API: `enabled=true`, `allowed_actions=all`, существующие workflow `active`.
Повторный dispatch всё равно отклонён с тем же HTTP 422; требуется проверить ручной
запуск во вкладке Actions и сообщаемую GitHub причину. Общие разрешения уже включены,
не нужно повторно менять их или подключать платные услуги. На компьютер владельца ничего не установлено,
локальные Rust-сборки и запуск приложения не выполнялись.
