# ODIBO PDF — этап 3.2: базовые компоненты egui

Дата: 2026-10-23. Ветка: `feature/odibo-uiux`. Основа: `main` после PR №2,
`23af123ae3ed5be1dd36fe09e76bc4b411e1b7eb`. Структура этапа 3.1 утверждена владельцем.

## Границы реализации

Только дизайн-система и существующая верхняя панель. Dashboard, новая навигация,
перестановка панелей и этапы 3.3–3.7 не реализуются в этом PR.

В `theme.rs` заданы размеры в логических точках: основной текст 13 pt, подписи инструментов и режимов
14 pt, второстепенный текст 12 pt, основные кнопки 32 pt. Масштабирование по-прежнему
выполняет существующий `ui_scale`; формат настроек не меняется. Статусы инструментов
увеличены с 9.5 до 12 pt с соответствующим увеличением плашек. Длинные подписи
по-прежнему ограничены шириной панели и доступны полностью через подсказку/AccessKit.

Активный режим имеет ограниченную поверхность, контур, полужирную подпись и нижнее
подчёркивание. Активная команда инструмента имеет контур и боковую метку; состояние
выводится из существующего `QuickTool`, без отдельной сохраняемой копии. Кнопки режимов,
каталога, поиска и другие базовые рисуемые кнопки получают видимый клавиатурный фокус.

## Верхняя панель

- «Сохранить» — основное подписанное действие с существующим `file.save` и проверкой
  доступности. Подсказка показывает штатное сочетание клавиш для платформы.
- Печать и свойства документа доступны через существующее «Меню → Файл», поиск команд
  и сочетания клавиш. Команды `print.dialog` и `file.properties` сохранены.
- Ширина режимов рассчитывается по переведённым подписям. Если места мало, текущий
  режим становится кнопкой выбора всех пяти существующих режимов.
- Поиск команд получает доступную ширину и переходит к подписанной в AccessKit иконке
  при нехватке места. `Ctrl+K`/`⌘K` остаётся прежним.

Переходы используют `switch_mode` и `run_command`: завершение редактирования, права PDF,
диалоги открытия и сохранения сохраняют свои прежние пути. Порядок и идентификаторы
панелей, сохранённая компоновка, CLI, MCP, PDF-ядро и файлы пользователей не изменены.

## Проверки и снимки

Проверки выполняются только на стандартных GitHub-hosted runners. Локально Rust,
зависимости и приложение не устанавливаются и не запускаются.

Новые проверки охватывают доступность режимов/поиска на узкой панели, отсутствие
пересечения элементов, состояние доступности сохранения без документа, выбор инструмента
через реальную команду, AccessKit selection, отсутствие изменения документа при выборе
инструмента, клавиатурную активацию и видимый фокус, сохранность пользовательских настроек.
Отрицательный контроль заменяет только `mode_tab` предыдущей реализацией и требует
падения теста структурного контура, после восстановления требует прохождения.

Workflow `ODIBO egui components` снимает настоящий `PdfCraftApp` через
`egui_kittest`/wgpu: редактор EN/RU, светлая/тёмная тема, компактное окно при 150% DPI.
Это не HTML-макеты этапа 3.1. Синтетический PDF содержит только оригинальные векторные
прямоугольники, без сторонних изображений и шрифтов. Системные шрифты отключены;
используется утверждённый pinned craft-fonts. Артефакт содержит происхождение и SHA-256.
Логотипы сохраняют отдельные условия `LicenseRef-ODIBO-Brand`; лицензии открытых
компонентов и оригинальные уведомления PdfCraft не меняются.

Актуальные результаты по коммитам, ссылки на артефакты и итог визуальной проверки
публикуются в описании и вкладке Checks [PR №3](https://github.com/imranOdiboev/pdfcraft/pull/3).
Полная проверка остальных крейтов, Windows и WASM выполняется штатными PR-workflows.
Артефакты Actions хранятся семь дней; скрипт воспроизводит снимки из конкретного коммита.

Первый прогон (`39843899293`) обнаружил конфликты имени Save с диалогами, два тесных
интерфейса при глобальном увеличении основного шрифта и ошибки настройки новых тестов.
Проверки не отключались: сохранено прежнее уникальное имя Save со shortcut в AccessKit,
основной шрифт оставлен 13 pt, увеличены второстепенный текст и подписи инструментов;
системные шрифты отключаются только для опубликованных снимков. Тест сохранности
настроек проверяет сам toolbar отдельно от существующей нормализации доступности
инспектора на Home.

Компактный снимок 720 pt — стресс-проверка ниже штатного Windows-минимума 820×520.
Отдельный снимок 820×600 проверяет существующую минимальную ширину. Автоматическая
перестановка/скрытие боковых панелей не входит в этот этап; при узком окне область PDF
остаётся ограниченной прежней компоновкой. Владелец сможет оценить изменение panel
layout отдельно на следующих этапах.
Проверка на физическом Windows-устройстве и с конкретным экранным диктором остаётся
отдельной ручной приёмкой; headless-тесты не подменяют её.
